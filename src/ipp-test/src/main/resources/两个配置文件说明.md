# application.properties 与 application-mysql.properties 说明

## 使用自己的库/表时还要 data.sql 吗？为什么会重复成 280 行？

- **连已有 MySQL、表里已有 93 行时**：不需要再让项目执行 data.sql。应把 `spring.sql.init.mode` 设为 **never**，否则每次启动都会再执行一遍 data.sql，在原有数据基础上再插入 93 行，启动 3 次就约 93×3≈280 行。
- **data.sql 适合**：仅在新库、空表、或本地 H2 测试时用；用完后（或连已有库时）务必改为 `never`，避免重复插入。

# application.properties 与 application-mysql.properties 说明（原）

这两个不是「仓库」，而是 **Spring Boot 的配置文件**，用来决定应用连哪个数据库、端口等。

---

## 两个文件分别代表什么

| 文件 | 作用 | 何时生效 |
|------|------|----------|
| **application.properties** | **默认配置**。当前写的是 **H2 内存数据库**（`jdbc:h2:mem:testdb`）。 | 不激活任何 profile 时使用（直接运行主类或 `mvn spring-boot:run` 时默认用它）。 |
| **application-mysql.properties** | **MySQL 配置**。里面已经写了 MySQL 的 **数据库 URL**、驱动、用户名等。 | 只有**激活了 `mysql` 这个 profile** 时才会生效，会覆盖/补充默认配置里的数据源。 |

所以：**数据库 URL 要加在「准备用的那份配置」里**。  
- 若要用 MySQL 并在客户端里看到表数据变化 → 在 **application-mysql.properties** 里填好 URL 和密码，并**用 mysql 配置启动**（见下）。  
- 若继续用 H2 → 不需要改 URL，数据在内存里，可用 H2 控制台查看。

---

## 为什么“增加操作返回 1 但数据库没变”？

- **返回 1** 表示插入成功，说明请求已经写入了**当前配置所连的库**。
- 当前**默认**用的是 **application.properties**，即 **H2 内存库**，数据在进程内存里。
- 如果你在 Navicat/DBeaver 等里看的是 **MySQL**，那当然不会变——应用根本没连 MySQL，所以要在 **application-mysql.properties** 里配好并**用 mysql 配置启动**，才能在你看到的那个 MySQL 库里看到变化。

---

## 要在哪个文件添加数据库 URL？怎么让 MySQL 里看到变化？

**在 `application-mysql.properties` 里配置即可**（URL 已有，一般只需改这两处）：

1. **必填**：`spring.datasource.password=` 改成你的 MySQL 密码。
2. **按需**：若库名、端口、主机不是默认的，可改 `spring.datasource.url`，例如：
   - 库名不是 `ipp_test`：把 URL 里的 `ipp_test` 改成你的库名。
   - 端口不是 3306：把 `3306` 改成你的端口。
   - 主机不是本机：把 `localhost` 改成服务器 IP 或主机名。

**然后让应用“用这份配置”启动**（二选一）：

- **方式一**：IDE 运行配置里，**Active profiles** 填：`mysql`。  
- **方式二**：命令行启动时加参数：`--spring.profiles.active=mysql`。

这样应用就会连你在 **application-mysql.properties** 里填的 MySQL，增删改查都会反映在你用客户端连接的那个库里；在 **application.properties** 里不需要再写 MySQL 的 URL。

---

## 小结

- 两个都是**配置文件**，不是代码仓库；数据库 URL 写在**准备启用的那份**里。
- 想让“你看到的那个数据库”有变化：在 **application-mysql.properties** 里填好 URL 和密码，并用 **profile=mysql** 启动应用。
